# 本机剪辑工作台 · 0.16.4

在 `character-showcase-studio-editor-dev` 开发目录内运行 `start-editor.cmd`，访问 <http://127.0.0.1:19378/>，点击顶部「剪辑工作台」。展示工作台仍可独立使用；剪辑与编码需要本机 Node 服务。Cloudflare 线上页面提供展示模板与本机剪辑入口，素材处理和视频导出由本机服务运行。

这台电脑的视频组件已经配置好。迁移到新电脑时，先安装 Node.js 和 Chrome 或 Edge，然后运行一次 `setup-editor.cmd`。FFmpeg 从官方列出的 Windows 构建提供方下载并校验 SHA-256；Playwright 只用于驱动已有浏览器逐帧渲染，不需要另外安装 Chromium。可用 `STUDIO_BROWSER=msedge` 指定 Edge；默认先找 Chrome，再找 Edge。

## 剪辑操作

展示工作台顶部「信息边框」旁新增「边框外观」入口，跳到右侧「边框外观、文字与滚动 · 全局 → 自定义边框颜色与样式」。未启用边框时，点击入口先启用上下信息边框。选择「自定义颜色与样式」后，可分别设置底色、文字色和强调色；外观提供纯色底板、细线描边、双线描边，并可调整底板不透明度与描边线宽。底板透明度不影响文字。选择默认配色可恢复原来的深色底板和随方案变化的强调色；「恢复默认边框」清除自定义设置。

边框外观由所有方案共用，支持横屏、竖屏、上下或左右边框。它随视觉模板和剪辑工程保存，应用于展示预览、剪辑合成、监视和实际视频、HTML、OBS 输出。AE 包带入对应底色、文字色、透明度和原生描边，CONTROLS 新增 Border Background / Border Ink / Border Accent / Border Background Opacity。旧工程维持原有外观。`tests/check-border-appearance.mjs` 在隔离服务检查入口、13 套方案、画幅、保存恢复、AE 场景及实际 ProRes 边框像素；HTML / OBS 保存和 AE 包校验纳入原有测试。

1. 拖入或选择视频、透明 MOV、PNG、JPEG、WebP。文件名没有 MIME 信息的 MOV 也会交给 FFmpeg 识别。导入只加入素材库，点击素材只选中；从素材库拖到时间轴对应轨道和时间位置才添加片段，目标轨道会高亮。可反复拖入同一个素材。
2. 时间轴上拖动片段修改开始时间；点击片段，在右侧输入精确开始时间、素材入点与出点。播放头位于片段内部时点击「分割」。支持删除、复制、撤销、重做和上移叠放顺序。
3. 「变换与裁切」提供位置、缩放、旋转、不透明度与四边空间裁切。素材始终以等比例适应画布为初始状态。
4. 「过渡与声音」设置淡入、淡出、滑入滑出或缩放过渡，素材音量可设置为 0 静音。重叠片段可以用上层片段淡入做叠化。
5. 「色度键」选择背景颜色、容差、边缘柔化和绿色溢色抑制。「素材调色」独立调曝光、对比度、饱和度和色相；左侧的全片调色作用于整个最终合成，包括信息边框。

轨道从上到下为：

- 边框上方素材。
- 固定的信息边框。
- 后处理上方素材：保持原画，不接受画面后处理。
- 固定的画面后处理。
- 文字上方素材：接受后处理，盖住片头、展示页和片尾文字。
- 片头、展示页和片尾文字。
- 文字下方素材：接受后处理，位于展示背景和图片之上。
- 原有展示背景、图片和场景内容。
- 音轨 1、音轨 2：与视频原声混合。

同一轨道后加入的片段盖在先加入的片段上方，可在属性中上移。展示工作台中选择视觉方案、边框、叙事与后处理，返回剪辑时会使用当前设计。剪辑全片时长可独立延长；原有叙事动画按自身设定演进。

## 透明 MOV 与预览

导入会先生成编辑用轻量预览：长边最多 960 像素、最高 30fps，保留原始视频。普通素材使用 H.264 预览；透明 MOV 使用保留 Alpha 的低分辨率 VP9 无损代理。尺寸和帧率合适的透明 VP9 WebM 直接复用，跳过转码。VP9 的 `alpha_mode` / `ALPHA_MODE` 标签均能识别，即使探测像素格式显示 `yuv420p`，也不会误判为不透明。

普通播放直接由浏览器合成视频；色度键使用 GPU，缺少 WebGL 时回退到低分辨率 CPU 路径。播放时视频自然前进，仅在开始、跳转或进入片段时定位；暂停后不持续重画同一帧。展示包装只由剪辑播放器绘制一次，并以较低画布像素密度预览。

导出直接连续解码原始视频，按源时间戳选取需要的帧，不使用低分辨率编辑代理，也不再为整段视频生成全尺寸 VP9 中间代理。透明 VP9 显式使用支持 Alpha 的解码器。帧以原尺寸、8 位 RGBA 无损 PNG 传入画面合成，避免额外的 YUVA 4:2:0 中间转换；浏览器合成仍为 8 位，不能把它视为端到端 10/12 位或 HDR 流程。原始视频不上传网络。旧工程无需重新导入。

已用 ProRes 4444 MOV 验证 Alpha 导入和输出，直接检查了透明与不透明像素。H.264、H.265、AV1、VP9 和常见 FFmpeg 支持的容器同样走本机解码流程。MOV 是容器，是否有 Alpha 取决于实际编码；某些特殊 HEVC 辅助透明轨道仍取决于 FFmpeg 解码器的支持，不能仅凭 `.mov` 后缀保证。

## 输出

左侧设置宽度、高度、帧率、全片时长、编码器与目标平均码率，再点击「导出视频」。输出逐帧合成展示画面、动画、素材、抠像、调色、层级和边框，不依赖屏幕实时录制，因此慢速渲染不会掉帧。素材声音按入点、出点、开始时间、音量和淡入淡出混合。

| 编码器 | 容器 | 透明通道 | 码率 |
| --- | --- | --- | --- |
| H.264 | MP4 | 无 | 目标平均码率 |
| H.265 | MP4 | 无 | 目标平均码率 |
| AV1 | MP4 | 无 | 目标平均码率 |
| VP9 | WebM | 可保留 Alpha | 目标平均码率 |
| ProRes 4444 | MOV | 可保留 Alpha | 质量编码，码率由编码器决定 |

勾选「透明背景」时需要使用 VP9 或 ProRes；包装中的不透明文字、边框与素材仍然保持不透明。逐帧输出耗时取决于分辨率、片长与效果，支持取消。H.264 / H.265 / AV1 的宽高必须是偶数。范围：64–7680 px、1–60 fps、0.1–250 Mbps，最长 1 小时。

## 保存与迁移

剪辑参数会自动保存到开发目录的 `.studio-media/project.json`，上传素材及其代理在 `.studio-media/assets/`，渲染视频在 `.studio-media/exports/`。刷新页面可恢复剪辑。点击「保存剪辑工程」会另外下载 JSON，打开工程时会校验本机素材。JSON 不嵌入视频，迁移时需一起复制 `.studio-media` 文件夹。展示工作台的设计参数仍沿用原有保存机制，原有图片上传的会话限制保持不变。

服务仅监听 `127.0.0.1`；原始素材目录不能通过静态路径访问。渲染和修改接口校验本机来源与会话令牌，只提供应用需要的素材与导出操作。

## 验证

`npm run check:editor` 检查片段边界、裁切、分割连续性、过渡透明度、色度键对原始 Alpha 的保留和输出参数。启动本机服务后，`node tests/check-editor-browser.mjs` 验证工作区切换，`node tests/check-editor-integration.mjs` 验证实际透明 MOV 导入、三种层级、分割/撤销、含声音 H.264 导出以及 ProRes 透明输出。原有 `npm run check` 继续验证展示、OBS、AE 和动画功能。

预览专项验证：`node tests/check-editor-preview.mjs` 验证透明 VP9 WebM 的实际像素、连续播放不反复定位、直放时不复制到画布、GPU 色度键及低清预览与全尺寸素材分离。测试服务可通过 `STUDIO_MEDIA_STORE` 指向独立临时目录，避免修改正在编辑的工程。

## 0.12.2 直接操作、同步配色与 GPU 编码

在剪辑视口点击素材即可选中并拖动移动；拖四角保持比例缩放，拖顶部圆形柄旋转。按住 Shift 可锁定移动方向、按 15° 旋转吸附或按 5% 缩放吸附。Esc 取消正在进行的拖动。每次完整拖动只记录一步撤销。

选择时间轴片段后按 Delete 删除；不删除素材库和原始文件。Ctrl+Z 撤销，Ctrl+Shift+Z 重做；在数字框或文本输入中按 Delete 仍然编辑文字，不会删除片段。

素材库每项旁有「删除」按钮；若时间轴引用了这个素材，会先显示关联片段数量，确认后将素材和关联片段一起从当前工程移除。可撤销/重做恢复，刷新后保留删除结果；本机原始素材文件和代理保留，便于撤销恢复。

剪辑页「展示页同步素材」和展示工作台「同步剪辑素材」是同一个开关，随剪辑工程保存。开启后，返回展示工作台仍可看到当前时间的剪辑素材、层级、抠像与全片调色，可以边看合成边改配色、后处理和边框；切换视觉方案会自动把素材接入新的画面。展示页自身的播放与时间进度也驱动素材。关闭后恢复仅预览原展示包装。该开关只控制工作台预览，不改变视频导出内容。

输出里的「编码设备」可选自动、CPU 和本机实际可用的 NVIDIA NVENC / Intel QSV / AMD AMF。设备列表通过试编码确认，自动模式会优先用 GPU；若该尺寸或设备暂不可用，会回退到 CPU 并显示原因。明确选择 GPU 时遇到失败会报错，不会静默改为 CPU。H.264/H.265/AV1 可使用硬件编码；VP9 Alpha 和 ProRes 4444 仍使用 CPU 编码保留透明度。

进度显示实际编码设备和合成帧率。逐帧网页合成与最终视频编码是不同阶段，GPU 编码不能省去画面合成成本；此版本同时改用快速无损 PNG 截帧、保留画布合成提交的必要等待以防止截取旧帧，并在可用时用同一个 WebGL 抠像着色器处理全尺寸导出。普通兼容 H.264 MP4 可直接复用原文件，避免首次导出时再生成巨大的无损 VP9 中间文件。

验证：`tests/check-editor-interaction.mjs` 覆盖移动/旋转/缩放、输入框保护、Delete/撤销、同步开关和切换方案；`tests/check-editor-hardware.mjs` 实际生成 NVENC H.264/H.265/AV1，并检查输出编码器元数据以及不同时间帧的红/蓝像素，并逐帧验证全尺寸 GPU 抠像的透明度。

## 0.12.3 连续解码导出

导出对每个活动片段连续解码，按实际时间戳取帧，支持可变帧率、裁切入点、同一素材的不同片段以及不同输出帧率。相同源帧只传给浏览器一次；后台提前读取下一帧，与当前画面合成重叠。只保存当前帧、一次预取和有界管道缓冲，不把整段影片解码到内存或磁盘。

分辨率、输出帧率、码率和编码器设置保持不变。中间 PNG 只降低压缩计算量，不丢失解码后的像素。首次使用较晚的入点仍会从头解码并丢弃前面的帧。画面合成、滤镜和无损截帧依然有成本，4K/60fps 不保证实时导出。

本机同一段 4 秒、1920×1080、30fps 透明 VP9 素材叠加展示包装，以相同 H.265 NVENC 设置测试：120 帧的合成与编码输入阶段从 36.0 秒降到 17.3 秒，约 2.1 倍。含初始化的总时间约从 38.1 秒降到 21.6 秒，约快 1.8 倍；不同工程会有差异。进度显示「连续解码」与实际合成帧率。

`tests/check-editor-frames.mjs` 验证完整 RGBA 像素、透明与半透明 VP9、可变帧率、时间起点、管道分块、重复帧、释放和取消。`tests/check-editor-preview-export.mjs` 验证原分辨率与透明度，以及不生成整段视频代理。诊断时可在启动服务前设置 `STUDIO_EXPORT_PIPELINE=browser`，暂用原来的浏览器定位流程；默认使用连续解码。

## 0.12.4 文字下方素材轨道

时间轴下方新增「片头文字下方」与「展示页文字下方」两条可拖放的素材轨道，也可以在片段的「合成层级」中切换。两条轨道接受画面后处理，原有三条轨道保持不变。

片头轨道跟随片头场景显示：双镜头片头会在第一幕/第二幕间自动接入，素材处于镜头图片上方、标题与说明文字下方；传统片头则接入其文字下方。展示轨道位于展示页的背景/几何装饰上方、姓名与说明文字下方。场景结束后，相关素材的画面及声音隐藏；片段的开始时间和入点仍按时间轴计算，需要把片段放在对应场景的时间范围内。

支持视口变换、裁切、抠像、淡入淡出、展示工作台同步及连续解码导出。`tests/check-editor-text-tracks.mjs` 检查两幕片头与传统片头的叠放顺序、场景隐藏、全部视觉方案的展示同步、实际输出像素、分场景声音以及工程保存隔离。

## 0.12.5 剪辑横竖屏画幅

在剪辑页左侧「输出设置 / 全片调色」顶部，可选择「剪辑画幅」：横屏16:9、竖屏9:16或自定义宽高。预设切换保留当前分辨率长边，例如3840×2160切换为2160×3840；不会降低分辨率档位、帧率或码率。修改自定义宽高会自动选择对应的横/竖屏排版。正方形使用横屏排版。

从展示工作台手动进入剪辑，会继承展示工作台当前的横/竖屏画幅；刷新直接打开剪辑时，以已保存的剪辑尺寸为准。竖屏不只是改变画布外框，标题、说明、双镜头片头和文字下方轨道均使用竖屏布局。剪辑预览、展示同步和原尺寸视频输出保持一致。已有素材保留原有变换百分比，可在视口内进一步调整构图。

`tests/check-editor-portrait.mjs` 验证预设尺寸、竖屏排版与视口适配、自定义比例、撤销/重做、从展示页继承、刷新恢复，以及实际竖屏视频导出。


## 0.12.6 · 独立色散与文字遮挡

展示工作台「画面后处理」新增「RGB 色散强度」：0–100%，默认 25%。0 关闭 RGB 分离，保留棱镜光带、原有辉光和其他效果；100% 对应旧版的色散幅度。该设置随设计保存，预览和本机视频导出共用。

原先两个随场景隐藏的文字轨道，替换为「文字上方」「文字下方」。两者均按片段时间持续显示和播放声音；「文字下方」位于背景、原展示图片之上，片头和展示页文字之下；「文字上方」还可覆盖这些文字。需要在片头与展示页使用不同遮挡关系时，在切换处分割片段，分别设置层级。旧工程的两个“文字下方”轨道自动按新“文字下方”规则显示，片段位置、时长与变换保留。

文字层使用原有文字节点及透明场景容器独立合成，不复制整张不透明展示页面。关闭展示页素材同步或切换方案时恢复原有结构。导出不再按旧轨道的场景时间窗裁切视频和声音。


## 0.13.0 · 自由拖轨、关键帧与监视窗口

- 时间轴片段可以横向改时间、纵向跨轨道拖动；固定的文字、边框等参考行不可放置。跨轨拖动作为一次操作撤销／重做。
- 「过渡与声音」新增独立声音淡入与淡出秒数。画面淡入淡出和透明度关键帧不再改变音量。旧工程未设置独立声音时，先沿用原来的画面淡入淡出数值；新片段默认声音不淡入淡出。
- 「属性关键帧」支持水平／垂直位置、缩放、旋转、不透明度。将播放头移到片段内，选择动画属性，添加关键帧；移动播放头后修改对应变换数值，会自动记录新关键帧。该属性已有关键帧时，视口移动、旋转、缩放也会记录当前帧。可跳转、删除关键帧，设置到下一帧的匀速、平滑、保持变化。插值按源素材时间计算，分割和裁剪保留原动画时序；视频导出使用同一套数值。
- 新工程默认「时长模式：自动」，全片时长跟随片头＋展示＋片尾（关机效果已包含在片尾）。直接输入全片时长会切换到自定义。旧工程明显不同于当前叙事的时长会保留为自定义。自动模式不会为了长素材延长全片；超出全片的片段部分不会导出。
- 侧栏按钮可分别收起素材库和属性；「放大预览」收起两侧并压缩时间轴；拖动时间轴顶部横条调整高度，也可聚焦该横条后按上下键。预览在缩放与调整窗口后保持居中并适应视口。
- 「独立监视」打开单独的网页窗口，自动跟随当前画面、关键帧和播放头，保持静音，不写入剪辑工程。监视窗口内点击「始终置顶」，通过桌面 Chrome／Edge 的网页画中画显示真正的置顶窗口；「取消置顶」或关闭画中画恢复普通监视窗口。需要允许站点弹出窗口；不支持网页画中画的浏览器仍可用普通监视窗口，并会明确提示。独立窗口使用编辑代理预览，导出仍读取原素材。


## 0.13.1 · 默认置顶的纯画面监视

「独立监视」现在直接打开置顶画中画，不再先开普通窗口再手动置顶。默认内容区域 960×540，无网页工具条、标题、播放按钮或置顶按钮；浏览器自身的关闭边框仍由浏览器管理。加载完成前保持黑底，不闪现编辑界面。关闭后可再次从剪辑工作台打开。

### 同版导出加速与帧完整性

原尺寸源帧改为本机内存 PNG URL 传输，避免逐帧把大段 base64 图像嵌入浏览器脚本。默认使用两个独立浏览器合成画面，共用一条按时间前进的源解码队列，按正确顺序编码；源解码、合成和输出预取保持有界。截图仍保留两次动画帧提交，透明度、变换关键帧和原尺寸像素处理规则共用原有实现。

浏览器截图保持无损 PNG，以内部 AVI/MPNG 帧包送入编码器，绕过裸 PNG 连续输入在大尺寸下的偶发解析错误；这不是新的视频导出格式，也不重压缩 PNG 或落盘整片帧图。流头使用 FFmpeg 非寻址管道支持的无限长度语义，实测 5.19GB、4000 帧仍完整。编码完成后检查输出视频包数与应有帧数一致，再报告完成。输入 PNG 解码固定单线程，避免高分辨率帧线程占用过多内存。

本机相同素材、设计、输出尺寸、帧率、码率、NVENC 编码预设下的实测如下；短片的完整耗时包含浏览器启动与编码收尾，项目内容不同会影响提升幅度。

| 测试片段 | 更新前合成／完整耗时 | 更新后合成／完整耗时 |
| --- | --- | --- |
| 1080p / 30fps / 4秒 | 19.56／25.63秒 | 5.87／9.68秒 |
| 4K / 60fps / 1秒 | 10.18／14.09秒 | 7.64／11.62秒 |

透明与半透明 Alpha、五项属性动画、重叠片段独立裁切、PCM 声音包络、棱镜／胶片后处理和取消后重新导出均有回归验证。1080p 对比的 120 帧逐像素相同；另有连续 180 帧 4K/60fps 完整性检查。

诊断时可用 `STUDIO_EXPORT_WORKERS=1` 限制为一路合成，`STUDIO_EXPORT_FRAME_TRANSPORT=base64` 比较旧的源帧传输，`STUDIO_EXPORT_CAPTURE_PACING=display` 比较浏览器显示节奏。它们不改变输出分辨率、帧率或编码质量设置。`STUDIO_EXPORT_TRACE=1` 与 `STUDIO_EXPORT_VALIDATE_PNG=1` 只供开发排查，会额外消耗资源。

## 0.14.0 两条独立音轨

素材库支持 MP3、WAV、FLAC、M4A、AAC、OGG、Opus、AIFF、WMA 等常见音频；带封面图的 MP3 仍识别为音频。导入后拖到时间轴下方的「音轨 1」或「音轨 2」，可重复使用同一素材，在两条音轨之间拖动。视频和图片继续使用画面轨道。

## 0.15.0 统一文字、视频和后处理层级；简化关键帧

剪辑画面的顺序与时间轴一致（从上到下）：边框上方素材 → 信息边框 → 后处理上方素材（不受效果）→ 后处理 → 文字上方素材（受效果）→ 片头 / 展示页 / 片尾文字 → 文字下方素材（受效果）→ 原有展示背景和图片。两条独立音轨仍在底部。

文字上下的素材、文字本身和原有场景内容在同一个合成表面中接受滤镜和光效；不会对文字重复套用滤镜。文字下方素材仍高于展示背景、展示图片及角色图，场景切换不会挡住整段视频。信息边框保持独立。旧「后处理下方」片段对应新的「文字上方 · 受后处理」轨道；旧两种「文字下方」轨道仍对应「文字下方 · 受后处理」。工程无需重新导入。

右侧「关键帧动画」提供「记录当前变换」：一次记录位置 X/Y、缩放、旋转和不透明度。之后移动播放头，在视口拖动、旋转、缩放或修改数字，即可自动记录对应属性；位移的 X/Y 成对更新。当前帧、前后关键帧和缓动方式可直接操作；「按属性调整」提供整体变换、成对位置或单个属性的添加 / 删除，以及保留当前姿态并清除全部动画。旧的单属性动画继续可用，编辑位置时会在同一时刻记录 X/Y。分割与裁切仍使用源素材时间保持动画连续。

验证：`tests/check-editor-text-tracks.mjs` 检查片头、作者页、展示页的实际遮挡像素、两种文字轨道接受同一后处理、绕过效果的上方轨道、旧轨道对应、13 种设计、实际视频和声音导出、同步关闭后的还原。`tests/check-editor-simple-keyframes.mjs` 检查一键五属性、直接拖动自动记录成对位置、数字修改及插值、成组缓动和导航、成对添加/删除、清除/撤销、分割和刷新恢复。

## 0.15.2 负缩放与镜像

素材「缩放 %」支持 −800% 到 800%。负值做左右镜像，例如 −100% 与 100% 等大、−50% 为一半大小并左右反转；高度使用缩放的绝对值，不会意外同时上下倒转。「水平翻转」按钮直接切换缩放正负号；「垂直翻转」单独切换上下方向，可以组合使用。0% 为零大小，可用于关键帧缩放动画。正负之间的连续缩放会经过 0%，需要瞬间翻转时将前一个关键帧的缓动改为「保持」。

负缩放可记录到原有缩放关键帧；镜像后仍支持视口拖动、旋转、等比缩放和四边裁切，预览与最终导出使用同一变换。垂直翻转是片段固定设置，随工程、复制和分割保留；「重置变换」恢复正常方向。旧工程未设置垂直翻转时默认关闭。

## 0.16.0 新增同类视频轨道

## 0.16.2 多核与 GPU 并行导出

移除原有 4K 最多两路、更大尺寸仅一路的固定限制，按照可用 CPU 线程、空闲内存、输出像素数和实际帧数分配最多八路合成。多路画面分配到最多四个独立浏览器进程，分散 GPU 合成进程的集中瓶颈。源素材共用严格按时间顺序读取的解码器，避免重复解码；源视频解码、无损 PNG 帧打包及编码器的 PNG 输入解码使用有上限的多线程。每路仍只保留一帧待编码画面，按时间轴顺序送入同一个最终编码器。

输出设置新增「导出并行度」：默认自动，可选择 1 / 2 / 4 / 8 路，并随工程保存。实际数量受空闲内存、输出表面总像素和总帧数限制；大尺寸不会直接启动八个全尺寸表面。进度显示实际合成路数。旧工程默认使用自动分配。同一服务内缓存最多 32 个不可变原素材的精确时间索引，再次导出无需重新扫描这些素材；缓存不包含整片解码画面，重启服务后清空。

2026-10-25，在 i9-13900K / RTX 5090 / 128GB 内存机器上，用当前工程的隔离副本测试，保持原尺寸源素材、H.264 NVENC p4 / HQ、30Mbps、相同视觉配置与声音。完整耗时包含准备、浏览器初始化与编码收尾；后续导出可复用时间索引，实际速度随内容与其他程序负载变化。

| 测试 | 原两路合成 | 新版八路 / 四进程 |
| --- | --- | --- |
| 1080p / 60fps / 8秒，首次导出 | 64.53秒 | 31.04秒 |
| 1080p 合成阶段平均速度 | 8.85帧/秒 | 26.17帧/秒 |
| 1080p / 60fps / 8秒，再次导出 | 每次仍扫描素材 | 23.19秒 |
| 4K / 60fps / 1秒，首次导出 | 25.43秒 | 15.52秒 |

首次接受每个合成进程的画面前，先在同一时间点预热并重新提交画面，避免高分辨率首帧的 GPU 表面尚未完成时漏掉片头图片和文字。八路 4K 的第一帧与单路预热参考逐帧比较，均保留完整内容。

不改变分辨率、帧率、码率、编码预设、原尺寸 RGBA 处理或透明通道保留规则。透明/半透明素材、重叠裁切、五项变换动画和 PCM 声音保持逐像素/逐样本一致；光效测试只容许极少量 GPU 滤镜的 1/255 RGB 舍入差，Alpha 必须完全一致。NVENC H.264 / H.265 / AV1、GPU 色度键、ProRes/VP9 Alpha、取消与重新导出、旧工程和手动并行度保存均有验证。

开发诊断可用 `STUDIO_EXPORT_WORKERS=1` 和 `STUDIO_EXPORT_BROWSERS=1` 限制为单路单进程；不要用多项同时运行的基准比较导出速度。自动预算测试为 `tests/check-editor-performance.mjs`，界面保存测试为 `tests/check-editor-performance-ui.mjs`，多进程像素、音频和取消测试为 `tests/check-editor-parallel-export.mjs`，设置 `STUDIO_TEST_4K=1` 可额外验证八路 4K 首帧。浏览器测试应使用独立素材目录和端口，不能指向正在编辑的工程。

## 0.16.3 可选 24 路激进导出

「导出并行度」增加 12 / 16 / 24 路，最高分配八个独立浏览器进程。这里的路数是同时合成的画面数量，不等于固定占用相同数量的 CPU 线程。激进档同时把共享源解码、源 PNG 打包和编码输入解码各提高至最多八线程，依然使用原尺寸、无损帧传输和相同编码质量。每路一帧的有界队列、逐帧排序、透明通道和取消清理规则保持一致。

24 路初始化分批进行，避免同时创建全部页面导致浏览器加载超时。合成表面仍受原有总像素预算限制：1080p 可以启用 24 路，4K 最多八路，避免显存换页导致严重停顿。同时保留 55% 空闲内存预算，并受 24 路硬上限和实际帧数限制；空闲内存不足时会降低实际路数。进度显示实际数量。旧工程的自动模式仍最多八路。

2026-10-25 同一台机器、同一段 1080p / 60fps / 8 秒工程，单独串行测试，编码参数不变：

| 配置 | 合成速度 | 完整耗时 |
| --- | --- | --- |
| 8 路 / 4 进程 | 26.02 帧/秒 | 首次 30.94 秒；此前重复导出 23.19 秒 |
| 12 路 / 6 进程，激进线程预算 | 28.11 帧/秒 | 已缓存时间索引时 25.14 秒 |
| 24 路 / 8 进程，激进线程预算 | 26.76 帧/秒 | 首次 45.90 秒 |

24 路在这个工程上没有明显提高合成速度，页面初始化开销还会增加总耗时，因此没有把自动模式强制改为 24 路。短片建议自动；长片或更复杂的合成可手动比较 12 / 16 / 24 路的完整耗时，按实际结果选用。高占用本身不等于更快导出。

同一 1080p 工程的 480 帧，24 路与八路导出的解码 RGBA 哈希逐帧完全一致。另用单路参考验证 24 路透明素材、重叠裁切、变换关键帧、光效、PCM 音频、淡入淡出，以及取消后重新导出；24 路选项的数字保存与刷新恢复也通过检查。4K 首帧保留完整文字和图片。
